# 05. 開業・税務・契約の整理（第1.0版）

本書は一般的な整理であり、個別の判断は税務署・税理士・弁護士・各官公庁の案内で確認する必要がある。
内容は作成時点（2026年10月）の一般的な理解に基づく。制度は変わるため、提出前に必ず公式情報で確認すること。

## 開業時に行うこと

| 項目 | 内容 | 期限の目安 |
|------|------|-----------|
| 開業届（個人事業の開業・廃業等届出書） | 納税地の税務署に提出。e-Tax でも可［1］ | 開業から1か月以内 |
| 青色申告承認申請書 | 開業届と同時に出すのが簡単。最大65万円の特別控除の要件の一つ［2］ | 開業から2か月以内 |
| 事業用口座・クレジットカード | 私用と分ける。会計処理が大幅に楽になる | 開業時 |
| 会計ソフト | 月1,000〜2,000円程度。請求書発行と帳簿を一体で管理できるものを選ぶ | 開業時 |

法人化は、年間利益が安定して数百万円を超えてから検討する。初期は個人事業で十分である。

## 消費税（インボイス制度）

- 開業直後は原則として消費税の免税事業者だが、取引先が課税事業者の場合、適格請求書（インボイス）の発行を求められることがある［3］。
- 法人顧客が中心になるため、登録の要否は早めに判断する。登録すれば消費税の納税義務が生じる。2割特例などの経過措置の適用可否は国税庁の案内で確認する［3］。
- 見積・請求は税抜価格で提示し、消費税を別記する。

## 契約書で押さえる点

docs/templates/contract_outline.md に骨子を置いた。最低限、次を明記する。

1. 業務の範囲と納品物（診断レポートの候補番号を引用し、範囲外を明記）
2. 報酬と支払時期（着手時50%・納品時50%など）
3. 検収の方法と期間（納品後○営業日以内に異議がなければ検収とみなす）
4. 知的財産：納品物の利用権は顧客に、汎用部分（雛形・ライブラリ）の権利は自分に残す
5. 秘密保持と、顧客データの取り扱い範囲・保存先・削除時期
6. AI 出力の性質：誤りを含み得ること、最終確認は顧客が行うこと、結果の保証はしないこと
7. 責任の上限（受領した報酬額を上限とする等）
8. 解約条件（保守は1か月前通知）

最初の受注時に、骨子をもとにした契約書を一度だけ専門家に確認してもらう。

## Web ページに必要な表示

サービス案内ページで申込みを受ける場合、通信販売に該当し得るため、特定商取引法に基づく表記（事業者名、所在地、連絡先、価格、支払方法、提供時期、返品・キャンセル条件）を用意する［4］。
個人事業主の住所は、請求があれば遅滞なく開示する旨の記載で代替できる場合があるが、要件は消費者庁の案内で確認する［4］。

## 顧客データと API の扱い

- 顧客の個人情報を扱う自動化では、委託契約の中でデータの範囲・目的・保存先・削除時期を明記する。
- 使用する API 提供元の利用規約（入力データが学習に使われるか、保存期間、データの所在）を確認し、顧客に説明できるようにしておく。
- 顧客の API キーや認証情報は顧客側で発行してもらい、自分の端末に長期保存しない。

## 帳簿

- 本リポジトリの台帳（ledger/ledger.csv）は進捗管理用であり、税務上の帳簿ではない。帳簿は会計ソフトで作る。
- 台帳と会計ソフトの売上合計は月末に突合する。
