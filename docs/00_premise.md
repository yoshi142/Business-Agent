# 00. 前提：なぜ「投資」ではなく「事業」なのか

## 依頼の解釈

依頼は「元手10万円を1,000万円にする」。これは100倍である。
この目標を“再現性のある方法”で達成できる手段は限られるため、次のように解釈して進める。

- 10万円は“開業資金”として使う。
- 1,000万円は“事業の累計売上”として目指す（利益ではなく売上。利益目標は別に置く）。
- 期間は明示されていないので、18〜24か月を作業上の目安とする。

## 投資・投機で100倍を狙わない理由

| 手段 | 100倍に必要な条件 | 評価 |
|------|------------------|------|
| 株式・投資信託 | 年率7%で約68年。年率20%でも約25年 | 期間が合わない |
| FX・暗号資産のレバレッジ取引 | 連続して方向を当て続ける必要がある。1回の逆行で元本を失う | 期待値がマイナスになりやすく、再現性がない |
| 宝くじ・ギャンブル | 控除率の分だけ期待値がマイナス | 論外 |
| 低資本の事業（サービス・デジタル商品） | 元手は道具代。売上は労働と営業の量に比例して積み上がる | 時間と行動量を投入すれば到達は現実的 |

“元手の100倍”という目標は、金融商品では非現実的だが、事業では珍しくない。
たとえば1件30万円の仕事を34件受注すれば1,000万円を超える。元手の大きさとは関係なく、受注件数の問題になる。

## 選んだ事業：中小企業向け AI 業務自動化サービス

### 事業の内容

従業員1〜30名程度の中小企業に対し、問い合わせ返信・見積作成・請求書入力・日報集計などの“毎日の繰り返し作業”を、
Claude などの生成AIと既存ツール（スプレッドシート・メール・LINE）を組み合わせて自動化する。
診断（低額）→ 小さな構築（中額）→ 月額の保守・改善（継続）の三段階で売る。

### 選んだ理由

1. 元手がほぼ不要。必要なのはドメイン、API 利用料、会計ソフト程度で、10万円で十分に足りる。
2. 自分の手元にある道具（Claude Code と API）がそのまま商品になる。仕入れも在庫もない。
3. 中小企業の人手不足は構造的で、“作業を減らす”提案は断られにくい。
4. 1件あたりの単価が15〜50万円で、34件前後の受注で目標に届く。月額保守が積み上がれば受注件数はさらに減る。
5. 納品物がソフトウェアなので、2件目以降は1件目の資産を流用でき、時間あたりの売上が上がる。

### 検討して見送った案

| 案 | 見送った理由 |
|----|-------------|
| 物販（せどり・輸入） | 10万円では仕入れ量が足りず、回転にも資金が要る。利益率も低い |
| アフィリエイト・ブログ | 収益化まで6〜12か月かかり、その間の収入がゼロ。検索流入の変動も大きい |
| 汎用 SaaS を自作して販売 | 集客と開発を同時に行う必要があり、1人では売上が立つ前に息切れしやすい |
| プログラミング講師・コンテンツ販売 | 単価が低く、1,000万円には数百人規模の集客が必要 |

汎用 SaaS は、受託で作った自動化のうち需要の多いものを後から製品化する形で取り込む（詳細は 01_plan.md）。

## 到達の目安（どう1,000万円を積むか）

| 収益の種類 | 単価（税抜） | 件数の目安 | 小計 |
|-----------|------------|-----------|------|
| 診断（有料化後） | 3万円 | 40件 | 120万円 |
| 構築（小規模自動化1件） | 25万円 | 20件 | 500万円 |
| 月額保守・改善 | 4万円／月 | 10社 × 平均10か月 | 400万円 |
| 合計 | | | 1,020万円 |

この表は“目標を分解した例”であり、予測ではない。実際の単価と件数は営業の結果で決まる。
重要なのは、月に1.5〜2件の構築受注を1年半続ければ届く規模である、という点である。

## できないこと・保証しないこと

- 私（AI エージェント）は、契約・入金・顧客対応を代わりに行えない。営業と納品は依頼者の行動が必要である。
- 売上の達成は保証できない。到達しない主な原因は「営業量の不足」と「単価の下げすぎ」である（03_sales_playbook.md を参照）。
- 法務・税務の記述は一般的な整理であり、個別の判断は税理士・弁護士・各官公庁の案内で確認する必要がある。
